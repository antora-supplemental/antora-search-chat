= Changelog

All notable changes to this project will be documented in this file.

The format is based on https://keepachangelog.com/en/1.1.0/[Keep a Changelog],
and this project adheres to https://semver.org/spec/v2.0.0.html[Semantic Versioning].

== [0.1.24] - 2026-10-21

=== Changed

* **Search compound elevation:** `.valentus-search-compound` gains a subtle downward drop shadow (light and dark tokens via `--valentus-search-compound-shadow`, with `--valentus-shadow-float` when Valentus defines it). The dock layout shell stays flat; focus ring stacks on top of the resting shadow.

== [0.1.23] - 2026-10-21

=== Fixed

* **Dock chrome:** the sticky dock root is a layout shell only (no outer border, padding, or shadow). The stacked scope + input compound keeps the visible card.
* **Dock results width:** portaled Lunr menus use full width of the dock (`left`/`right` 0) so they align with the compound instead of theme navbar `left: 0` sizing.

== [0.1.22] - 2026-10-21

=== Changed

* **Default placement is `dock`.** The omnibox mounts as a sticky bar above the footer (navbar vacates). Set `placement: navbar` to restore the top-bar slot.
* **Placeholder copy** reflects enabled levels: *Search by keyword…*, *Search by meaning…*, and *… or ask…* when chat is on. Semantic mode does not split keyword vs semantic result zones (semantic search subsumes keyword Lunr hits).
* **Capability strip removed.** Disabled semantic search and chat are noted in the results menu footer instead of always-visible Keyword / Semantic / Chat checkboxes.

== [0.1.21] - 2026-10-21

=== Changed

* **Extension authors:** prefer `SoftNavSignals.subscribe(key)` for chrome; omnibox uses derived keys (`componentName`, `componentTitle`, `versionName`, `versionDisplay`, `context` → `syncScopeLabels`); `bindSoftNavContext` only for `onLoaded` / scope menu HTML from `detail.doc`.

== [0.1.20] - 2026-10-21

=== Changed

* **Breaking:** search partial and hooks use the `valentus-*` namespace (`valentus-search-chat` partial, `data-valentus-search-chat`, `--valentus-search-*` tokens) instead of legacy `adt-*`.
* **Docs:** `ARCHITECTURE.adoc` documents SoftNav vs SoftNavContext split (`onContext` + `onLoaded`) for omnibox scope refresh.

=== Fixed

* **SoftNavContext:** when `@antora-supplemental/soft-nav-context` is present, scope labels follow `SoftNavContext.on('context')`; full scope tree still refreshes from `detail.doc` on `loaded`.
* **Scope menu after SoftNav:** refresh `data-valentus-search-chat` attributes and scope tree from `soft-nav:loaded` / `SoftNav.on('loaded')` (`detail.doc`) so context rows do not go blank when the navbar/dock omnibox survives in-component navigation.
* **Dock flush to viewport bottom:** sticky dock uses `--valentus-search-viewport-bottom-gap` instead of `bottom: 0`; navbar placement keeps a small omnibox margin.

== [0.1.19] - 2026-10-20

=== Fixed

* **Scope bar was two hit targets.** The closed context control is one button covering the whole row. Hover lights the full bar at once, and a click on the lower half opens the menu. The top corners still follow the rounded search field.
* **Placeholder slash.** When the field is empty, *Search or ask...* is the normal hint and `/` is an inline code chip. The hint hides as soon as there is text and does not block clicks.

== [0.1.18] - 2026-10-20

=== Changed

* **One query field.** The placeholder is `Search or ask... /`. Search and Ask mode buttons are gone. Typing still runs keyword search; Enter asks. Shift+Enter inserts a newline only when the field is a textarea. `/` still focuses the field. The scope selector stays visible and is disabled only while an Ask request is in flight.

=== Fixed

* **Scope control painted square corners** over the rounded search field. The closed control is clipped inside the curve; the open menu is not.
* **Two scrollbars on results.** Lunr’s inner dataset no longer scrolls inside the results box. Keyword hits use one scrollport. When semantic search is on, keyword and semantic hits stack in two zones that scroll on their own, with no third bar around both.
* **Empty results border.** The results box stays hidden until a query has hits, an empty-state message, or an Ask reply is in progress.

== [0.1.17] - 2026-10-20

=== Fixed

* **Search dock covered the footer.** The dock is no longer a fixed overlay on the body. It mounts at the end of the page column (`.valentus-shell`, marked `valentus-search-dock-column`) and uses sticky positioning, so it stays on screen while scrolling and its layout box sits between the article and the footer. Footer links, the edit link, and the extension lister receive clicks.

== [0.1.16] - 2026-10-19

=== Fixed

* **Search overlay shell was still see-through.** Valentus paints `.valentus-nav-search` (including hover and focus-within) with `background: transparent !important`. The dock root carries that class, so the outer shell, mode tabs, and padding showed the page even when the inner card was filled. Search chrome now uses literal hex fills and higher-specificity `!important` rules so the dock, compound, scope menu, Lunr hits, Ask panel, capability chips, keyboard hints, and inputs stay opaque. Disabled scope and off capabilities no longer fade with `opacity`.

== [0.1.15] - 2026-10-19

=== Changed

* **Stable omnibox shell:** Search and Ask share one layout — scope row, query field, mode tabs below the input, optional Ask result in-flow. No floating Ask panel or layout swap when switching modes.
* **Scope in Ask mode:** context selector stays visible but is disabled/inactive while Ask is active.
* **Capability strip:** Keyword / Semantic / Chat indicators move to the bottom of the dock overlay.

=== Fixed

* **Opaque search chrome (follow-up):** scope/menu/result hovers and Lunr hit rows use `--valentus-search-surface-hover` and solid `--valentus-search-surface` fills instead of transparent theme soft tokens or Lunr defaults.

== [0.1.14] - 2026-10-19

=== Fixed

* **Transparent search chrome:** dock, compound, scope menu, collapsed popover, and Lunr results now use opaque `--valentus-search-surface` fills. Lunr’s `.search-result-dropdown-menu` default (`background: transparent`) no longer lets page content show through; rims use accent-on-border `color-mix` with optional soft outer rings in the shadow only.

== [0.1.13] - 2026-10-19

=== Fixed

* **Dock results ran off the top of the viewport:** the portaled Lunr results menu now caps at `min(65vh, 100vh - 12rem)` with internal scrolling, so the first results stay visible above the dock.

== [0.1.12] - 2026-10-19

=== Fixed

* **Dock anchored to the header, not the viewport:** the theme header's `will-change: transform` makes it the containing block for fixed descendants, so the dock rendered at the header instead of the bottom of the screen. The dock root is now portaled to `<body>` on init (capability/scope/result refs preserved), the vacated navbar slot collapses via an `valentus-search-slot-vacated` class, and the scope menu + Lunr results are portaled to direct dock children so they open above the whole dock box.

== [0.1.11] - 2026-10-19

=== Fixed

* **Dock placement was hidden by its own navbar slot:** the vacated `.valentus-navbar-search` host now collapses to a zero-size, overflow-visible box instead of `display: none`, which had hidden the fixed dock descendant as well.

== [0.1.10] - 2026-10-17

=== Fixed

* **Scope dropdown hidden behind the doc mast:** scope menu, collapsed popover, Lunr results, and Ask panel now use a top-layer z-index (`--valentus-search-top-z: 200`); paired with Valentus lifting `.valentus-site-navbar` above `.valentus-doc-mast` inside the sticky header, so search menus paint on top of everything.

=== Added

* **Floating dock placement** (`placement: dock`): fixed bottom dock — rounded outer box with a Keyword / Semantic / Chat capability strip (disabled status checkboxes, no emojis), stacked scope-above-input card inside; scope menu, Lunr results, and Ask panel open *upward* above the dock. Navbar remains the default placement.
* **Capability levels config:** `semantic_enabled` / `semanticEnabled` (or `semantic_backend_url`) exposes the semantic level in the runtime payload (`levels: { keyword, semantic, chat }`) and the capability strip. The hybrid semantic engine remains a separate track; this is its UI/config seam.
* **Enter = chat query:** typing still searches on keystroke (Lunr); pressing Enter in the search field submits the query to Ask when chat is enabled.

=== Changed

* Placeholder copy: main label is *Semantic Search* when the semantic level is enabled, else *Search* (*… or Ask* appended when chat is on). The muted note now reads *(Chat unavailable)* instead of *(AI mode not configured)*.
* Stacked search layout released: context selector above the input (`.valentus-search-compound--stacked`); ARCHITECTURE and compound diagram updated.
* README: canonical hub GitHub topics URL → `docs.antora-supplemental.org/docs/hub-github-topics/`.

== [0.1.6] - 2026-10-17

=== Fixed

* **`/` and `?` shortcuts:** call Valentus `window.adtRevealSiteChrome()` before opening Search/Ask so scroll-away navbar + mast peek back into view for typing.

== [0.1.5] - 2026-10-16

* Read `searchChat` overrides from `@antora-supplemental/facto-stack` pack config when search-chat is not a separate playbook require.
* Treat Lunr as present when the playbook requires facto-stack (compose pack registers Lunr before search-chat).

== [0.1.4] - 2026-09-09

* *Change:* Scope closed face drops the *Component*/*Version* kind prefix and shows the selected label only. Replace the native `<select>` with a static hierarchy tree menu (`All docs` → current component → versions, with *current* on the page version).
* *Docs:* Extract the compound-control layout into canonical Mermaid source and ship explicit Themed SVG standalone-adaptive and host artifacts with deterministic generate/check tooling.
* *Docs:* Consumer discovery topic is the bare repo name `antora-search-chat` (not `uses-*`); SemVer tag pins. Fan-out via skills `update-consumers` + `antora-extension-consumers`.

== [0.1.3] - 2026-08-01

* *Fix:* Theme toggle light↔dark — opaque omnibox chrome (`.valentus-search-compound`, scope slot, collapse toggle / popover, Ask panel) now transitions `background-color` / `color` / `border-color` with the page instead of snapping. Adds `--valentus-search-theme-transition` aligned with Valentus `--valentus-transition`.

== [0.1.2] - 2026-07-25

* Search dropdown edges, scope dual-tone labels, collapse-to-icon, scope caret mask, and related omnibox polish (see Valentus theme changelog for integration notes).
