= antora-search-chat
:toc:

Antora extension that **wraps** https://gitlab.com/antora/antora-lunr-extension[`@antora/lunr-extension`] with a Search / Ask omnibox — not a fork of lunr.

Status:: Phase 1 scaffold (stub UI + pluggable backend config). Product target is one field (*Search or Ask*); Ask is explicit (not AI-on-every-keystroke). No production LLM/RAG yet.

Package:: `@antora-supplemental/antora-search-chat` (not yet published to npm — install from git).

== Quick start

. Install (pnpm example):

[source,shell]
----
pnpm add -D github:antora-supplemental/antora-search-chat
----

. Register **after** lunr in the playbook:

[source,yaml]
----
antora:
  extensions:
    - require: "@antora/lunr-extension"
      index_latest_only: true
      index_by_heading: true
      snippet_length: 200
    - require: "@antora-supplemental/antora-search-chat"
      # Optional — see ARCHITECTURE.adoc
      # ask_enabled: true                 # force "Search or Ask" (even without backend)
      # backend_url: https://search-api.example.com/v1/ask   # also enables Ask; no API keys here
      # default_mode: search
      # local_assist: false
----

== Theme integration contract

The extension injects CSS/JS/partials into the UI catalog and sets `SITE_SEARCH_CHAT` so a theme can prefer `{{> adt-search-chat}}` over a plain lunr field.

Chrome hooks themes should provide (or accept the injected partial owning the slot):

* A search host such as `.adt-nav-search` / `.adt-navbar-search` / `#search-field` with `#search-input` (lunr contract).
* Room for the compound pill (scope + field) and results dropdown without clipping (`overflow: visible` on ancestors).

Reference integration: https://github.com/antora-supplemental/valentus-theme[Valentus theme] places the omnibox in the site navbar center.

Related (different product):: https://github.com/antora-supplemental/antora-ai-help-extension[antora-ai-help-extension] — in-page AI prompts, vector search, Q&A cache. This package is the lunr-first Search/Ask omnibox only.

== Placeholder UX

* Ask **on** (`ask_enabled: true`, or `backend_url` / `local_assist` set) — *Search or Ask*.
* Ask **off** — *Search* plus a deader *(AI mode not configured)*.
* Overlay hides when the field is focused or non-empty.

Optional site key:: `site.keys.askEnabled` — theme mirror if you wire a plain `#search-input` yourself. See ARCHITECTURE.

== Product shape (target)

* *One omnibox* — `/` and `?` set Search vs Ask mode on the **same** field (not two widgets).
* *Scope control* — dropdown *built into* the left edge of the field (*All docs* / *This component* / optional *This version*). Closed face shows dual-tone *Component* + muted current title (from Antora page context); menu options say *This component — {name}*.
* *Compound UI* — one pill: `[ Component {name} ▾ | Search or Ask ]` (`.adt-search-compound` + `.adt-search-scope-slot` / face + `.adt-search-scope`); shared border, inner vertical rule, full-height scope hit target.
* *Default scope* — *Current component* on docs pages when detectable; *All* on home / when ambiguous. See ARCHITECTURE.
* *Collapse* — on narrow / collision, omnibox collapses to a search icon; popover holds scope + input + Ask + lunr results.
* *Lunr-first* — keyword results while typing in Search mode; Ask only on explicit mode / submit. Optional debounced question-detection may come later; it is not the default.
* *Tier-0 local assist* (optional) — ultra-light on-device model for query rewrite / short answers over retrieved chunks; remote `backend_url` is an optional upgrade. Never put API keys in the playbook.
* *Upstream* — propose multi-value facet / filter API on lunr-extension; this package wraps store metadata first.
* *Layout* — compound control should live outside clipped nav columns so scope + results are not cut off.

Keyboard (when not typing in a field)::

* `/` — *Search* mode (lunr)
* `?` (Shift+/) — *Ask* mode on the same field

Hint badges show `/` and `?`. See ARCHITECTURE for the `key === '?'` vs `key === '/' && shiftKey` caveat.

Phase 1 stub may still show separate Search/Ask panels; compound scope markup/CSS may be visual-only until filters wire up. Product target is omnibox + conjoined scope.
